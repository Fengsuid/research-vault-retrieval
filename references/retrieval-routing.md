# 检索路由与覆盖要求

## 1. 查询类型 → 起点层

| 查询类型 | 起点 | 是否需要 Fulltext | 是否需要 PDF | 本轮证据上限 | 允许范围 |
|---|---|---|---|---|---|
| 论文定位（「有哪些论文研究 X」） | Note 索引 / 笔记正文 | 否 | 否 | L1 | 全部 Analytical Notes |
| 单篇概念、方法、结论 | 该篇 Note | 定义/变量/数字/原话时需要 | 否 | L2 | 一篇 |
| 原话/精确引用 | 该篇 Note → Fulltext | 是 | 否 | L2 | 一篇 |
| 页码/公式/表格/图 | Note → Fulltext → PDF | 是 | 需要 | L3 | 一篇 |
| 多论文比较 | 多篇 Note 矩阵 | 仅对需确认的定义、指标、参数、原话 | 视需要 | L2 | 已定位论文 |
| 综述 / 研究方向 / 共识与争议 | Note 候选池（必要时 Knowledge 导航） | 只对关键论据 | 视需要 | L2 | 覆盖面见 §3 |
| 某个说法是否被当前 Vault 支持 | Note 召回 → 关键证据 | 是（关键结论） | 否 | L2 | 召回范围 |
| 用户明确要求全文词搜索 | 直接 Fulltext（显式补充召回） | 是 | 否 | L2 | 标注 supplementary |
| Vault 之外的文献 | — | — | — | — | 默认不联外网；用户明确要求时才切换外部检索并标注 |

Knowledge 层只用于导航和候选发现（概念、方法、关系、争议、研究方向），**永远不能作为论文级证据**。任何 Knowledge 句子要落成证据，必须回到其 `source_notes` 指向的 Note，再按需进入 Fulltext。

## 2. 单篇问题的检索顺序

```
用户问题
 → 关键词（中英文术语、指标、方法）
 → find（notes 层）
 → 读 1–3 篇候选笔记
 → resolve（身份链）
 → 需要精确证据时 verify(targeted fulltext)
 → 需要页码时 verify(pdf page)
 → 回答 + 证据等级 + 缺口
```

单篇问题不要批量打开全文；比较类问题先用 Notes 建立 `方法 × 变量 × 结论 × 局限` 矩阵，再只对需要确认的格子进入全文。

## 3. 综述 / 研究方向类问题的覆盖要求

这类问题按 **paper-level 候选池**处理，不是「找到几篇就写」：

1. **候选发现**：多组语义不同的 query（同义词、指标、方法、机制、尺度、结果类型）分别 `find`，跨 query 合并候选池。
2. **按论文去重**：同一论文的 Note、全文、不同 query 命中只能计 1 篇。识别优先用 `zotero_key`，其次 DOI，最后唯一规范化标题。
3. **覆盖目标**：默认目标 **20 篇**，最低 **15 篇**（除非用户指定数量）。
4. **停止条件**（满足任一即可）：
   - 候选池达到目标篇数；
   - 多组语义不同的 query 都已无新论文加入；
   - 连续 2–3 个概念不同的扩展 query 只带来 ≤1 篇新论文，且不再出现新的指标、机制、方法、尺度或结果类型。
5. **不允许的停止理由**：单个 query 出零结果、结果互相重叠、已找到几篇高相关论文、已核验 5–7 篇。
6. **不足时如实报告**：少于 15 篇时必须报告 query、候选统计和 `has_more`/截断情况，并区分「Vault 数据不足」与「检索覆盖不足」。

覆盖块必须能回答：一共扫了多少笔记、候选多少篇、有全文多少篇、实际核验多少篇、哪些问题没有证据。

## 4. 什么时候可以扩大检索范围

仅以下情况可越过 NOTE-FIRST：

1. 用户明确要求「直接在所有全文里搜某个术语/原句」；
2. Note 召回明显不足，需要补充全文召回（每次都必须标注 `supplementary fulltext recall`，并把命中结果还原到 Note 身份）；
3. 需要核验 Note 无法判断的具体术语。

即使扩大，也必须回到对应 Note 获取论文身份和背景，再决定是否进入该篇全文。

## 5. 外部证据

默认 **Vault-only**。只有用户明确要求联网/外部论文时才切换，并在答案中区分「Vault 内证据」与「外部证据」，不得把外部结论混入 Vault 证据等级。
